# 돈 탐정 (Cost Detective) 설계 — "비용이 왜 바뀌었지?"

- 작성일: 2026-10-27
- 사용자 결정: "기본값으로 ㄱㄱ". 질문 단계를 건너뛰었으므로, 아래 기본값은 모두 **내가 정한 것**이다.
- 바탕: 비용 레이더(`src/lib/cost-radar/`)와 변경 기록(`src/lib/change-timeline/`)을 엮는다.

## 1. 왜 만드는가
공유 샌드박스 계정은 Cost Explorer가 SCP로 막혀 있다. 비용 레이더는 "지금 얼마"와 "7일 전보다 몇 %"는 보여 주지만, **왜 바뀌었는지**는 알려 주지 않는다. 변경 기록은 "누가 무엇을 만들고 지웠는지"를 안다. 둘을 합치면 "어제보다 월 $45 늘었어요 — 가장 큰 원인은 jiwoo님이 어제 만든 RDS(+$38)"처럼 답할 수 있다.

## 2. 목표 / 비목표 / 반목표
- **목표**
  - 두 시점 사이 월 예상 비용의 변화를 **리소스 단위의 원인 목록**으로 설명한다. 각 원인에는 금액 영향, 누가, 언제, 무엇을 했는지가 붙는다.
  - 기간은 어제 / 7일 / 30일 중에서 고른다. 계정 선택(All 또는 계정별)을 따른다.
  - 비용 레이더 페이지의 "돈 탐정" 패널, Slack 아침 요약, Slack 질문 "비용 왜 늘었어?"에서 보여 준다.
- **비목표**
  - 실제 청구서와의 대조. 지금도 추정치이고, 사용량 기반 비용은 제외한다.
  - 리소스를 끄거나 지우는 버튼.
  - 서울 외 리전.
- **반목표 (이렇게 되면 실패)**
  - 원인 금액의 합이 총 변화와 맞지 않는데 아무 설명도 없다. 차이는 반드시 "설명되지 않은 변화"로 드러낸다.
  - 근거 없는 사람을 원인으로 단정한다. 기록이 없으면 "누가 했는지 기록 없음"으로 쓴다.
  - 조회가 느려지거나 CloudTrail 한도를 넘는다. 새 CloudTrail 호출은 변경 기록 수집기만 하고, 탐정은 저장된 기록만 읽는다.

## 3. 기본값 (내가 정함)
1. **일별 리소스 스냅샷**
   - 비용 레이더가 하루 1번 이력을 기록할 때(`recordDailyIfMissing`), 계정별 **리소스 단위 가격 목록**을 함께 저장한다.
   - 파일은 `data/cost-radar/snapshots/YYYY-MM-DD.json`(KST 날짜)이고, 40일간 보관한다.
   - 담는 내용: `{id, name, category, monthly, detail}`
2. **비교 방식**
   - 기준은 N일 전(KST) 스냅샷이고, 현재는 실시간 추정치(비용 레이더 응답, 5분 캐시)다.
   - 리소스 id로 비교해 원인을 세 종류로 나눈다.
     - **새로 생김**: 현재에만 있다.
     - **사라짐**: 기준에만 있다.
     - **금액 바뀜**: 양쪽에 있는데 월 금액이 다르다. 정지·시작·크기 변경이 여기에 해당한다.
   - 금액 영향이 큰 순서(절댓값)로 정렬한다.
   - "총 변화 − 원인 합"은 "설명되지 않은 변화"로 표시한다.
3. **스냅샷이 아직 없을 때(처음 며칠)는 "기록 기반 추정" 모드**
   - 변경 기록에서 기간 안에 생성됐고 지금 살아 있는 리소스는 현재 가격으로 계산한다.
   - 삭제된 리소스는 "금액 알 수 없음"으로 둔다.
   - 화면에 "아직 비교할 과거 스냅샷이 없어서 기록 기반으로 추정했어요"라고 알린다.
4. **누가 했는지(귀속)**
   - 변경 기록에서 같은 리소스 id(S3는 이름)의 기간 안 기록을 찾는다.
   - 새로 생김은 create, 사라짐은 delete, 금액 바뀜은 아래 5번의 상태 변경 기록과 맞춘다. 가장 최근 기록을 쓴다.
   - 기록이 없으면 사람을 비워 둔다.
5. **변경 기록에 상태 변경 추가**: 정지·시작·크기 변경은 비용을 크게 바꾸지만, 지금 변경 기록은 생성·삭제만 모은다. 그래서 종류를 넓힌다.
   - `ChangeKind`: `create | delete | stop | start | modify`
   - EC2: `StopInstances` → stop, `StartInstances` → start, `ModifyInstanceAttribute` → modify(instanceType을 바꿀 때만)
   - RDS: `StopDBInstance` → stop, `StartDBInstance` → start, `ModifyDBInstance` → modify
   - EBS: `ModifyVolume` → modify
   - `/changes` 화면 문장: "…님이 EC2 서버를 껐어요 / 켰어요 / 설정을 바꿨어요"
   - 요약 숫자(생성·삭제)와 "만든 사람" 배지는 기존대로 create/delete만 쓴다.
6. **화면**
   - 비용 레이더 페이지에 "돈 탐정" 패널을 둔다. 비용 레이더의 기존 시안 v2 스타일(어두운 배경, 라임·핑크 강조, 둥근 카드)을 따른다.
   - 제목 문장 예: "지난 7일 동안 월 예상 비용이 $45 늘었어요" / "…$12 줄었어요" / "…거의 변화가 없어요(±$1 미만)"
   - 기간 칩: 어제 / 7일 / 30일
   - 원인 한 줄 예: "+$38/월 · jiwoo님이 RDS moyeota-test-db를 만들었어요 · 10월 25일"
   - 맨 아래 "설명되지 않은 변화 $3"
7. **Slack**
   - 아침 9시 요약에 한 줄 추가: "💸 어제보다 월 예상 비용 +$45 — 가장 큰 원인: jiwoo님 RDS moyeota-test-db(+$38)". 변화가 $1 미만이면 생략한다.
   - 질문 "비용 왜 늘었어 / 돈 왜 / 비용 변화"에는 지난 7일 설명을 규칙으로 답한다(AI를 거치지 않음).

## 4. 제약
- 가격은 비용 레이더의 내장 서울 가격표와 기존 `buildEstimate` 결과를 그대로 쓴다. 새 가격 계산은 만들지 않는다.
- 스냅샷 기록은 기존 일별 기록과 같은 수집 결과를 재사용한다(Steampipe 추가 조회 없음).
- 날짜는 모두 KST다(기존 history와 같은 `kstDay`).
- 앱 규칙
  - fetch는 `/api/*`, 컴포넌트는 default export
  - i18n은 ko/en/zh 3개 파일
  - 오류 응답에는 이름만 담는다
  - `data/cost-radar/`는 이미 gitignore돼 있다
- 변경 기록의 `ChangeKind` 확장은 기존 화면·Slack·creators 동작을 바꾸면 안 된다. 생성·삭제 숫자, 만든 사람 배지, "누가 만들었어" 답이 그대로여야 한다.
