# Terraform 코드 변환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn console-created AWS resources (picked via the dependency graph) into Terraform code that passes a `terraform plan` diff-0 gate, with rule-first fixes, AI-assisted leftovers, deterministic references/naming/layer files, secrets moved to sensitive variables, and pass-rate metrics.

**Architecture:** `src/lib/tf-export/` holds pure text transforms (HCL block utils, rules, refactor, plan-JSON judging, zip) plus thin adapters (Terraform executor with an allowlist, Bedrock fix calls, Steampipe listener lookup). A single-job pipeline (`job.ts`) runs stages prepare → generate → rules → ai-fix → diff → refactor → verify → package in `data/tf-export/jobs/<id>/`. `/api/terraform-export` and `/terraform-export` drive it. Terraform 1.9.8 + AWS provider 5.100.0 are installed by `scripts/18-setup-terraform.sh`.

**Tech Stack:** Next.js 14, TypeScript, vitest, Node `child_process.execFile`, `zlib`-free store-only zip, Tailwind.

**Spec:** `docs/superpowers/specs/2026-10-29-terraform-export-design.md` (Korean; §6 overrides earlier sections).

## Global Constraints
- Terraform subcommands allowed: `version`, `init`, `plan`, `show`, `validate`, `fmt` only. Reject any argv containing `apply`, `import`, `state`, `destroy`, `-auto-approve`, `-target`, `console`, `taint`, `untaint`, `force-unlock`, `workspace`. `plan` flags allowed: `-input=false`, `-no-color`, `-out=<file>`, `-generate-config-out=<file>`, `-detailed-exitcode`, `-refresh=true`. Common env: `TF_IN_AUTOMATION=1`, `TF_INPUT=0`, `CHECKPOINT_DISABLE=1`, `TF_PLUGIN_CACHE_DIR=<data/tf-export/plugin-cache>`. Run via `execFile('nice', ['-n','10', TF_BIN, ...])`; 10 min per command (12 min cross-account), 30 min per job.
- Versions: Terraform `1.9.8`, AWS provider `5.100.0`, `required_version = "= 1.9.8"`. Binary `/home/ec2-user/awsops/.tools/terraform` (resolve as `path.join(process.cwd(), '.tools/terraform')`).
- One job at a time process-wide (no queue); starting while running → 429. Max 60 resources per job. One account + its configured region per job.
- Secrets: Lambda environment variable values, and values whose key matches `/password|secret|token|credential|privatekey|apikey/i` → never sent to the AI, never in the bundle (→ `variable { sensitive = true }` + `terraform.tfvars.example` with `CHANGE_ME`), real values only in `<job>/secrets.auto.tfvars`, deleted at package along with `generated.tf`, `plan.bin`, plan JSON, logs.
- AI output rejected if it contains `provisioner`, `local-exec`, `remote-exec`, `data "external"`, `data "http"`, a `provider`/`module`/`terraform` block, or any resource address other than the one being fixed.
- Logs: `[tf-export]` prefix, error names only; never log credentials, HCL bodies or plan values.
- AWS: read-only usage only (Terraform plan reads; STS AssumeRole for other accounts; Steampipe SELECT).
- Bilingual one-line comments (English then Korean); components `export default`; `fetch('/api/...')`; i18n keys `tfExport.*` + `sidebar.tfExport` in ko/en/zh.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. An AI "fix" that adds a provisioner, new provider or a different resource address — must be rejected and counted as a failed fix (Task 6).
2. A secret (Lambda env value, `master_password`-like key) reaching the AI prompt, the zip, `report.json`, or remaining on disk after package (Tasks 5, 6, 7).
3. Reference refactor creating a cycle (two SGs referencing each other) — verify falls back to un-referenced bundle; shipped bundle is always the last diff-0 one (Task 7).
4. A resource removed after failing must also lose its `import` block, or the whole plan errors (Tasks 2, 7).
5. Executor called with a forbidden subcommand/flag (e.g. via a crafted file name) — rejected before spawning (Task 3).
